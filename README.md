# Лабораторна робота №4 — Layered Architecture (Java)

Цей проєкт реалізує вебзастосунок на **Java (Spring Boot)** з REST API за патерном **багаторівневої архітектури**.
Тема лабораторної відповідає предметній області з `Laba1–Laba3`: **система обслуговування клієнтів готелю** (бронювання, заселення/виїзд, додаткові послуги).
При реалізації API орієнтація зроблена на контракт із `Laba2/openapi.yaml`.

## Обрана предметна область

Система обслуговування клієнтів готелю (онлайн-бронювання номерів, заселення/виселення, запити до сервісів, базова автентифікація).

## Структура шарів

- `presentation` — REST-контролер `HotelController` та глобальна обробка помилок `GlobalExceptionHandler`.
- `application` — бізнес-логіка `HotelApplicationService` (правила доступності номерів, перевірка станів бронювання, токен-аутентифікація).
- `domain` — доменні сутності та доменні помилки (`User`, `RoomType`, `Room`, `Booking`, `ServiceItem`, `ServiceRequest`, `HotelException`).
- `data` — in-memory збереження/seed даних `InMemoryHotelDatabase` (імітація БД).

## 5 реалізованих сценаріїв

1. **Реєстрація гостя** — `POST /api/v1/auth/register`
2. **Вхід у систему** (отримання токена) — `POST /api/v1/auth/login`
3. **Перегляд типів номерів та доступних номерів** — `GET /api/v1/room-types`, `GET /api/v1/rooms?checkIn&checkOut&roomTypeId&minCapacity`
4. **Створення бронювання** — `POST /api/v1/bookings` (статус `pending`, конфлікт якщо номер недоступний)
5. **Заселення/виїзд + додаткові послуги**:
   - заселення — `POST /api/v1/bookings/{bookingId}/check-in` (бронювання стає `active`, номер `occupied`)
   - виїзд — `POST /api/v1/bookings/{bookingId}/check-out` (бронювання `completed`, номер `available`)
   - запит послуги — `POST /api/v1/service-requests` (для активного проживання)

## Атрибути якості

### 1) Модифікованість
- Вся бізнес-логіка зосереджена в `HotelApplicationService`.
- Дані зберігаються через in-memory реалізацію (`InMemoryHotelDatabase`), яку можна замінити на БД без зміни контракту REST.

### 2) Тестованість
- Є інтеграційний тест `HotelControllerTest` з `MockMvc`.
- Шари ізольовані: контролер не містить складних правил доступності.

### 3) Надійність
- Валідація вхідних даних через `jakarta.validation`.
- Контрольовані відповіді на помилки через `GlobalExceptionHandler` (HTTP-код + `code` в JSON).

### 4) Зрозумілість/підтримуваність
- Код структурований по шарах з чіткими відповідальностями.
- Назви методів і сценаріїв відповідають use-case з попередніх лабораторних.
